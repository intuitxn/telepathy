# Historical Buzz and Bend worker route

This guide records the earlier OpenCode, Buzz ACP, and Lorenz Bend worker arrangement. It is archival for the new Telepathy source tree. The current algorithm source is [`runtime/core/telepathy.bend`](../core/telepathy.bend), run through the [pinned DSH host](../dsh/README.md) with host-owned grants and independent evaluation. The [operator guide](../../OPERATE.md) gives the current source checks; the [reconciliation map](../../docs/designs/local-main-reconciliation.md) covers legacy state and cutover.

The earlier worker used immutable local Bend snapshots for claims, packets, reported returns, explicit learning, and correction. Its loopback HTTP acknowledgement meant delivery, not completion. Selected Buzz engrams were separate summaries and did not automatically merge the snapshot lineage or inherit its dependency checks. The installed Buzz Desktop, an owner-controlled signer, and native ACP were outside this repository's trust boundary. Earlier checks did not establish that arbitrary worker answers were correct or that credentials were isolated from execution processes.

The old `/meta agents` command, Meta shell, and Mundus host entry points are retired from this source tree. An installed process may still be running and retain private state. Preserve its sessions, receipts, and workspaces during a coherent backup and deliberate switch; do not reclassify an old reported result as accepted DSH knowledge. The [historical route note](../adaptive/META.md) describes its relation to the new machine.

The prior JTBD Buzz workflow used `request_approval`, which the inspected engine returned as `approval_not_supported`. Its existence was not an enforced review gate. For current team communication use the authorized Buzz identity and [project review rules](../../docs/PROJECT_REVIEW.md); a Buzz message does not create a DSH task. The [relay setup record](../../docs/RELAY_SETUP.md) is dated evidence, not current service status.
